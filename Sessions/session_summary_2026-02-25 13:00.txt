## Goal
Fix Validate and Publish pipeline steps so the full Import Catalog → Candidate Registration pipeline works end-to-end.

## What Was Done

### 1. Validate & Publish buttons called wrong function
- Both buttons called `openReviewDialog()` (opens review panel) instead of `governedTransition()` (triggers stage transition)
- Fixed: changed onClick to `governedTransition(entry, "validate")` and `governedTransition(entry, "publish")`
- Added disabled state until review is approved, Rocket icon, spinner while transitioning
- File: `client/src/pages/CandidatePage.tsx` lines ~975 and ~1200

### 2. PUB-05 "Review approved" check used tags instead of stageReviews
- Lifecycle transitions replace tags (registered → validated), not accumulate them
- PUB-05 checked for both `registered` AND `validated` tags simultaneously — impossible
- Fixed: now checks `stageReviews.register === "approved"` and `stageReviews.validate === "approved"`
- File: `server/governance/stage-review.ts` lines ~604-618

### 3. Unused "approve" lifecycle stage blocked validate→publish
- LIFECYCLE_STAGES had: ingest → submit → register → validate → **approve** → publish
- The lifecycle guard requires sequential transitions (diff = 1)
- validate→publish had diff = 2 (skipping approve), so it was always blocked
- Fixed: removed "approve" from LIFECYCLE_STAGES and all related tag mappings
- File: `server/governance/lifecycle-guard.ts`

### 4. stageReviews missing from stageReview query and stageTransition handler
- Both `governance.stageReview` query and `governance.stageTransition` mutation built entry objects WITHOUT `stageReviews`
- PUB-05 evaluator always got `{}`, so "Missing approval: register, validate" even when approved
- But `catalogManage.approve` DID pass stageReviews — creating the contradiction (approve succeeds, checklist shows failure)
- Fixed: added `stageReviews: (dbEntry as any).stageReviews || {}` to both handlers
- File: `server/governance/router.ts` lines ~513 and ~562
