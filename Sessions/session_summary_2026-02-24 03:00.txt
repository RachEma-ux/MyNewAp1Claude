## Objective
Make evidence persistence non-fatal in the governance engine, fix discovery flow end-to-end, and fix auto-classification for discovery submissions.

## Problem
The `persistEvidenceBundle()` function in `server/governance/scorecard/evidence.ts` was doing a blocking DB insert that threw on schema mismatch. This error propagated through `requireGate()` → `requireGovernance` middleware → killed ALL governed mutations with 500 INTERNAL_SERVER_ERROR, even when the governance gate PASSED (e.g., score 89).

Additionally, `submitFromDiscovery` was missing the auto-classify step, causing the registration stage review's `compliance_matrix` check to fail with "No classification assigned".

## Changes Made

### 1. evidence.ts — Non-fatal persistence (prior commit, carried forward)
- Wrapped `persistEvidenceBundle()` DB insert in try/catch
- Logs warning on failure instead of throwing

### 2. requireGate.ts — Phase A/B architectural refactor
- **Phase A (Enforcement, blocking):** Freeze check → scorecard → denial audit + denial evidence
- **Phase B (Observability, non-fatal):** ALLOW evidence persistence → ALLOW audit log
- Each Phase B operation wrapped in try/catch with structured error logs:
  - `NON_FATAL_EVIDENCE_PERSISTENCE_FAILURE`
  - `NON_FATAL_AUDIT_LOG_FAILURE`
- No silent catch blocks — all failures logged with subject_type, subject_id, stage, run_id
- Freeze denial now uses `FREEZE_BLOCK` audit action (was `GATE_CHECK`)

### 3. requireGate.test.ts — New test file (6 cases)
- CASE 1: Scorecard ALLOW + persistEvidenceBundle throws → returns ALLOW
- CASE 2: Scorecard DENY + persistEvidenceBundle throws → returns DENY
- CASE 3: Freeze active → DENY, scorecard never runs
- CASE 4: Normal operation → unchanged behavior
- CASE 5: ALLOW + audit log throws → returns ALLOW with local fallback ID
- CASE 6: DENY path → audit + evidence both blocking

### 4. catalog-manage.ts — Auto-classify discovery submissions
- Added auto-classify block to `submitFromDiscovery` mutation (lines 262-271)
- Assigns first taxonomy axis node after entry creation
- Matches behavior of the regular `create` mutation
- Non-fatal: wrapped in try/catch
