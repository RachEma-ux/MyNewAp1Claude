4. KNOWN LIMITATIONS CARRIED FORWARD
================================================================================

- Termux + npx stdio MCP servers: `npx @modelcontextprotocol/server-filesystem`
  fails with `env: 'node': Permission denied` (exit 126). Termux SELinux
  restricts child exec of node from within a spawned process context. The
  new stderr capture surfaces the real error so users can diagnose.
  Workaround: use `node` directly with the package's main file instead of
  going through the `env node` shebang. Verified with an inline node MCP
  one-liner as the local-fs seed row.

- Async "ask" permission flow in the dispatcher — treated as sync deny
  (decision #3a). The simulation engine still has the long-poll pending-
  request path; the dispatcher's sync nature means it can't use it.

- Per-tool governance decision cache (R3 mitigation) — not implemented.
  Will matter if evaluateMcpPreInvoke becomes a bottleneck.

- Event streaming UI bus — no event bus infrastructure yet. FSM transitions
  are emitted via setImmediate to a local EventEmitter (#9b async dispatch),
  but there's no SSE endpoint surfacing them to the browser yet. The MCP
  Manager page uses 5s polling instead.

- Sandbox isolation for stdio MCP servers (Phase 19d) — parked until a
  3rd-party MCP marketplace ships. All MCP servers today are user-attached
  on a single-trust-boundary host.

- tools/list_changed notification handlers — the registry supports
  republishSnapshot but no transport currently subscribes to the
  notification. Future per-transport work.

- Phase 18 openllm-agent2 fork patch — MyNewAp1Claude side (configure_session
  adapter) shipped as 93f5a2e earlier. The fork side (types.ts / ws-bridge.ts
  / headless-engine.ts patches documented in
  docs/agent-studio/option-a-openllm-agent2-patches.md) is still the user's
  manual next step — requires creating a fork of RachEma-ux/openllm-agent2
  and applying the 3 documented patches.
