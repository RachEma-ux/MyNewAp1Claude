### 1. Deployed and tested tech docs auto-discovery on ai21.com

### 2. Fixed: governance.stageReview field name mismatch (ed3b29b)
- Bug: The governance router's stageReview query and stageTransition mutation passed `entryId`/`entryName` from tRPC input directly to `evaluateStageReview()`, which expects `id`/`name`
- Symptom: PUB-01 "Cross-doc consistency" showed "Missing: name" in the UI preview even when entry had a name
- Fix: Map `entryId` → `id` and `entryName` → `name` in both the query and mutation handlers in `server/governance/router.ts`

### 3. Fixed: stage review badges turning all green on Register approve (abb9eef)
- Bug: `approveCatalogEntry()` was called for every stage, setting legacy `reviewState: "approved"` even on Register-only approval. The UI fallback treated this as all stages approved.
- Fix (client): Removed legacy `reviewState` fallback from `getStageReviewState()` — each stage badge only shows "Reviewed" from explicit `stageReviews` JSON
- Fix (server): Only set legacy `reviewState: "approved"` when the publish stage passes

### 4. Fixed: auto-propagate lifecycle tags on stage approval (1959273)
- Bug: Approving Register didn't add `registered` tag, so Validate's VAL-11 "Audit trail complete" check failed
- Fix: The approve endpoint now automatically adds lifecycle tags (`registered`, `validated`, `published`) when each stage is approved
- Also auto-activates entries on Validate approval

### 5. Fixed: PUB-05 circular dependency with legacy reviewState (45695e4)
- Bug: PUB-05 required `reviewState === "approved"` but we deferred setting it until publish — creating a chicken-and-egg problem
- Fix: PUB-05 now checks `stageReviews.register === "approved" && stageReviews.validate === "approved"`, with legacy `reviewState` as fallback
- Added `stageReviews` to `ReviewContext` interface and passed it in all `evaluateStageReview()` calls
- Updated publish endpoint to accept stageReviews-based approval check
