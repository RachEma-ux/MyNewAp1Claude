### 1. Fixed Wizard Handoff Readiness Crash (ROOT CAUSE)
The PS Wizard Handoff was permanently showing "Complete required steps to unlock wizard handoff" even when all 11 steps were green.

**Root cause discovered**: The `readiness.evaluate` tRPC endpoint was crashing with a 500 error due to schema mismatches between Drizzle ORM definitions and actual DB tables:
- `ps_ideation_screening_scores` missing `scored_by` column
- `ps_ideation_scenarios` missing `created_by` and `updated_by` columns
- `ps_ideation_feasibility_checks` missing `created_by`, `updated_by` columns + had `finding1`/`finding2` instead of expected `finding_1`/`finding_2`

The 500 error meant `readiness` was `undefined` on the client, causing the UI to fall through to the "Complete required steps" message.

**Fix**: Added missing columns via ALTER TABLE (applied locally) and created migration file `drizzle/0032_ps_ideation_schema_sync.sql` for CI/deploy persistence.

**Verified**: Both ideations (42, 43) now return `ready: true` with 0 blockers.

Commit: `9a58170` — tagged as `v99.99.141` (stable)

## Key Learnings
- Drizzle ORM crashes silently when DB columns are missing — the SQL query includes all schema-defined columns, and PostgreSQL throws an error if any don't exist
- The readiness endpoint 500 error was masked on the client as `undefined` readiness, not as a visible error message
- `trpc.useUtils().path.query.fetch()` is the correct way to call a tRPC query imperatively (returns a promise)
