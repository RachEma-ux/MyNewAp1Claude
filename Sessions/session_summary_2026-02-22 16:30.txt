## What Was Done

### Candidate Pipeline — Tag-Based Stage Progression (Major Feature)
Implemented a complete pipeline where entries flow through stages via tag updates:

**Flow:** Submit → Register → Validate → Publish → Catalog

1. **Import/Submit** — entry gets tag `"candidate"`, `origin: "discovery"` → appears in Register tab
2. **Register** (admin approval) — tag changes `"candidate"` → `"registered"` + entry approved → appears in Validate tab
3. **Validate** (admin approval) — tag changes `"registered"` → `"validated"` → appears in Publish tab
4. **Publish** (admin approval) — tag changes `"validated"` → `"published"` + entry activated → appears in Catalog

### Key Design Decisions
- **No cloning** — same entry moves through pipeline via tag updates (not duplicated)
- **History in each tab** — each tab shows entries at its stage AND all later stages (e.g., Register shows candidate + registered + validated + published)
- **Processed entries show badges** — once an entry is progressed, the action button is replaced with a status badge (e.g., "Registered", "Validated", "Published") preventing duplicate clicks
- **Validate is admin approval** — not a technical probe (provider doesn't exist yet during pipeline)
- **Rich cards in all tabs** — Validate and Publish tabs show full entry details (description, origin, reviewState, tags, classification badges, updated date) matching Register tab layout
- **Catalog page** filters by tag `"published"` (not `"candidate" + active`)
