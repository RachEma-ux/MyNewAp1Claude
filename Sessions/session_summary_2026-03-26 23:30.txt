### Debugging Journey
1. Tested backend via curl — all API calls (classify, create, list) worked perfectly
2. Confirmed systems existed in DB after wizard flow
3. Realized the list page query itself was broken — not a create problem but a READ problem
4. Verified: `curl /api/trpc/ps.systems.list` with no input → "invalid_type: expected object, received undefined"
5. Fix: `.optional().default({})` on the Zod schema

### Key Lessons Learned
- tRPC useQuery() with no args sends `undefined`, NOT `{}`
- Zod z.object({...}) rejects undefined even if all fields are optional
- Fix pattern: add .optional().default({}) to schemas used by no-arg useQuery()
- tRPC errors in React Query are swallowed by default (show loading → empty state)
- Always test the exact same call path the frontend uses (no input, not {})
- Governance requires BOTH action-key-map.ts AND platform_action_registry.yaml entries
- runAutomaticProcessing was a static mock — never derived from actual user input
