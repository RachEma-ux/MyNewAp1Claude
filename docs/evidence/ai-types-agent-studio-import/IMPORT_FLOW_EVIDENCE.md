# AI Types ⇐ Agent Studio Import — Flow Evidence

**Captured:** 2026-05-04 against main@8517385.

The Plan v3 import flow that lets an AI Types user pull a published
Agent Studio agent into the catalog. Sister evidence to
`docs/evidence/provider-model-binding/`.

---

## Flow at a glance

```
AI Types client
   │
   │  (Phase 35 UI — deferred. Catalog Import Modal "Import from Agent Studio" entry.)
   ▼
trpc.aiTypes.import.*  (AI Types-side tRPC router — owned by AI Types module)
   │
   │  delegates to:
   ▼
server/ai-types/import-from-agent-studio.ts
   │
   │  gatewayCall({ ctx: { sourceModule: "aiTypes",
   │                        targetModule: "agentStudio",
   │                        actionKey: "agentStudio.exportCatalog.exportCandidate",
   │                        governanceReceiptId: "aitypes-import-<agentId>-<ts>" },
   │                input: { agentId, registeredBy } })
   ▼
agentStudio.exportCatalog.exportCandidate (Phase 30 gateway action, receipt-required)
   │
   │  prepareExportRegisterPayload (Phase 31 nine-gate eligibility)
   │  → asserts eligibility before forwarding
   │
   │  gatewayCall({ ctx: { sourceModule: "agentStudio",
   │                        targetModule: "aiTypes",
   │                        actionKey: "aiTypes.catalog.register",
   │                        governanceReceiptId: "ags-export-<agentId>-<ts>" },
   │                input: prepared.registerPayload })
   ▼
aiTypes.catalog.register (Phase 25 gateway action, receipt-required)
   │
   │  checkDuplicateLegacyImport (Phase 24 guard)
   │  → on collision: throw RegisterDuplicateError
   │  → on modern existing row: updateCatalogEntry
   │  → on no existing row: createCatalogEntry
   │
   │  emitRegisterAudit (Phase 38, best-effort)
   │  emitCatalogRegisteredEvent (Phase 39, best-effort)
   ▼
catalog_entries (sourceType="agent", sourceId=agentId)

   ↓ (Phase 39 event bus delivery)
   ↓
   ↓ subscribe: agentStudio  (Phase 40)
   ↓ → processCatalogSyncEvent
   ↓ → recordCatalogSyncEvent
   ↓
ags_catalog_sync_log (eventId-deduped, full payload preserved)
```

Every cross-module hop is a `gatewayCall`. Neither side imports the
other's internals.

## Boundary invariants enforced

- **AI Types → Agent Studio**: `server/ai-types/import-from-agent-studio.ts`
  is the *only* file in `server/ai-types/` that mentions Agent Studio.
  It uses `gatewayCall` exclusively (no `import "../agent-studio/..."`).
  Verified by:
  - `tests/pmb/boundary.test.ts` invariant 3
  - `tests/pmb/wiring.test.ts` "AI Types ⇐ AS import surface"
  - `scripts/check-ai-types-public-api-boundary.ts` baseline-allow lint
- **Agent Studio → AI Types**: `agentStudio.exportCatalog.exportCandidate`
  uses `gatewayCall` to invoke `aiTypes.catalog.register`. AS never
  imports `server/ai-types/db` or writes to `catalog_entries` directly.
  Verified by:
  - `tests/pmb/boundary.test.ts` invariant 2
  - `server/agent-studio/publish-no-catalog-write.test.ts`
- **No PII leak**: the export DTO carries no `apiKey`/`secret`/
  `releaseNotes`/`approvalStateJson`/`systemInstructions`/
  `roleInstructions` per the Phase 29 forbidden-key blocklist
  (recursive). Verified by `server/agent-studio/shared/export-candidate.test.ts`
  recursive forbidden-key test.

## Receipt threading

Both gateway hops are receipt-required:

| Hop | Action | Receipt id source |
|---|---|---|
| AI Types → AS | `agentStudio.exportCatalog.exportCandidate` | Stub `aitypes-import-<agentId>-<ts>` generated by `import-from-agent-studio.ts` if the caller doesn't pass one. |
| AS → AI Types | `aiTypes.catalog.register` | Stub `ags-export-<agentId>-<ts>` generated by `boot.ts` exportCandidate handler. |

Stubs are placeholders for the production receipt-policy
implementation; the gateway accepts them today because the descriptor
flag is `receiptRequired: true` and the gateway only verifies the
field is non-empty. A future hardening phase can switch to verifying
the receipt against a registry.

---

## Best-effort posture

Two best-effort writes happen during a successful import:

1. **Phase 38 audit event** — `catalog.register.created`/`updated`
   row in `catalog_audit_events`. If the audit insert fails, the
   register completes anyway; the audit failure is a `console.warn`.
2. **Phase 39 bus event** — `aiTypes.catalog.registered` published
   to the platform event bus. If the publish fails, the register
   completes anyway. Phase 41's `reconcileSync` repairs missed
   sync log rows on the next admin scan.

Neither failure rolls back the catalog write. The catalog row is
the source of truth.

## What's not yet wired

- **Phase 35 UI**: the Catalog Import Modal entry is a UI deferral.
  Functions in `import-from-agent-studio.ts` exist; an `aiTypes.import.*`
  tRPC router that wraps them does not yet exist as a registered
  action. When the UI lands, it will call those functions through
  the tRPC layer.
- **Production receipt registry**: receipts are stub strings today.
  A registry-backed verifier is a future hardening item, tracked
  outside Plan v3.
